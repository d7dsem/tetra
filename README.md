# tetra (PoC)

Офлайн-демодулятор TETRA π/4-DQPSK з IQ-файлів (WAV int16 2ch або raw `.cs16`).
Канального декодування (FEC/дескремблювання/деперемеження) немає: на виході
"сирі" демодульовані біти burst'ів плюс діагностика якості й виявлення полів TETRA.

Навігація по коду (де що шукати, збірка, потік даних): `docs/INDEX.md`.

## Структура репозиторію

```
bin/
  tetra_demod        - sh-обгортка запуску (знаходить свій каталог, cd, exec)
source-py/
  tetra_demod.py     - точка входу (CLI, argparse)
  config.py          - ЄДИНЕ місце всіх параметрів (секція CONSTANTS)
  front_end.py       - ресемплінг, RRC matched filter
  burst_search.py    - пошук burst'ів (поріг+гістерезис на matched-filtered сигналі)
  coarse_detect.py   - альтернативна груба детекція ДО matched filter (вимкнена
                       за замовчуванням, див. docs/cheat-shit.md)
  symbols.py         - символьна синхронізація (Oerder-Meyr)
  demod.py           - диференціальна демодуляція, мапінг дібітів
  snr_estimate.py    - SNR на сирому масиві, часовий метод
  snr_freq.py        - SNR, частотний метод (FFT)
  pattern_check.py   - пошук полів TETRA (FCF/NTS/STS/ETS/TAIL), звірено з
                       ETSI EN 300 392-2
  checks.py          - діагностичні перевірки (HealthReport findings)
  health.py          - модель Finding/CheckResult/HealthReport
  memcheck.py        - оцінка потрібної пам'яті ДО завантаження файлу
  pipeline.py         - оркестратор, викликає етапи по черзі
  io_stage.py        - читання WAV/raw, запис .txt/.bin/.bin2/.bin3
  synth.py           - генератор синтетичних сигналів для тестів
  test_*.py          - тести (unittest)
docs/
  cheat-shit.md      - практичні команди й шпаргалка (цей архів)
```

## Запуск

```bash
chmod +x bin/tetra_demod        # один раз
./bin/tetra_demod in.wav -o out
```

Працює з довільного каталогу (не лише з кореня репо), якщо `bin/` є у PATH
або викликається за шляхом - сам знаходить `source-py/` відносно себе.

## Вимоги до входу

**IQ-файл для `tetra_demod`** (`source-py/io_stage.py`, `checks.check_meta`, `front_end.to_work_rate`):
- формат: WAV int16, 2 канали (I, Q), або raw `.cs16` з обов'язковим `--fs`;
- частота дискретизації не нижче 36 000 Гц (2 x символьна швидкість 18 000), інакше фатальна помилка `FS_TOO_LOW`; будь-яка частота перераховується до 72 000 Гц (на 72 000 Гц ресемплінгу немає);
- тривалість не менше 0,02 с, інакше фатальна помилка `INPUT_TOO_SHORT`;
- сигнал в основній смузі, відхилення несучої в межах символьна швидкість / 8 = 2250 Гц (половина цієї межі - попередження, `HEALTH_COARSE_WARN_FRAC`).

**Файл бітів для `dmo_rx`** (`dmo/dmo_rx_entry.c`, `dmo/dmo_core/dmo_core.h`):
- виклик: `dmo_rx <файл> [-v] [-o STEM]`;
- вміст: потік байтів, кожен рівно `0` або `1` (один біт у байті), без заголовка й кадрування; перший біт у файлі - перший за часом; інший байт - помилка з вказанням зсуву;
- пошук burst'ів: DSB (STS точним збігом), DNB1 (преамбула P1 + NTS1 + tail 00) і DNB2 (P2 + NTS2 + tail 00) з допуском помилок із `dmo_tuning.h` (преамбула 1, NTS 2, tail 0); увесь burst довжиною 470 біт має вміщуватися в потік.

**Що робить `dmo_rx`.** Декодує SCH/S і SCH/H у DSB (CRC, поля: слот, кадр, шифрування, тип повідомлення, адреси, MNI), з DSB бере колір-код (`MNI mod 64` і адресу джерела з DM-SETUP, DM-CONNECT ACK або DM-OCCUPIED) і дескремблює ним DNB: DNB1 - SCH/F (з CRC) або TCH; DNB2 - STCH у першому блоці. TCH-блоки (432 біти type-4) записує у `STEM.out` у форматі входу ETSI-кодека (`cdecoder`); за замовчуванням STEM - ім'я входу без розширення. Підсумок і лічильники друкуються першими рядками (`#`), далі рядок на burst.

**Голос.** `bin/dmo_voice STEM.out [out.wav]` пропускає `.out` через встановлені в `/tetra/bin` `cdecoder` і `sdecoder` (кодек використовується як є, до коду не інтегрований; каталог - `TETRA_CODEC_DIR`) і пише WAV 8 кГц, mono, int16.

**Зв'язок етапів.** `.bin`, `.bin2`, `.bin3`, `.bin4` - біти, упаковані по 8 в байт (порядок бітів у байті - `-e LE|BE`), для `dmo_rx` вони не підходять. Для нього `tetra_demod` додатково пише `.bits`, `.bits2`, `.bits3`, `.bits4`: ті самі біти, що в `.bin`, `.bin2`, `.bin3`, `.bin4`, але один біт у байті (0/1) у порядку передачі, без упаковки і без залежності від `-e`; їх можна подавати в `dmo_rx` напряму.

## Тести

```bash
cd source-py
python3 -m unittest discover -p "test_*.py" -v
```

## Параметри

Усі в `source-py/config.py`, секція CONSTANTS. Перевизначення з командного рядка:
`--set група.параметр=значення` (можна кілька разів). `--print-config` показує
поточні значення у JSON.
