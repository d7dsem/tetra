# tetra_demod: алгоритм

**Призначення.** З IQ-запису радіоефіру зробити потік бітів кожного burst'а (короткого радіоімпульсу довжиною в один часовий слот) плюс діагностику якості. Каналів і голосу тут немає: це перший етап, його біти читає `dmo_rx` (`docs/algo-dmo-rx.md`).
**Вхід:** WAV (2 канали int16) або raw `.cs16`. **Вихід:** `out.txt` (burst'и й статистика), `out.bin` (біти, упаковані по 8), `out.bits` (1 біт = 1 байт, вхід для `dmo_rx`), а також `.bin2-4` / `.bits2-4` для перегляду структури. Формати - `docs/tetra-demod-internals.md`.

Пріоритет: **★** ядро (помилка тут = неправильні біти), **◐** важливо (вирішує, чи довіряти результату), **○** допоміжне (на біти не впливає).

## Алгоритм одним поглядом

Сигнал TETRA - π/4-DQPSK, 18 000 символів/с, по 2 біти на символ. Burst'и йдуть у часових слотах, між ними пауза. Тому послідовність така:

1. Привести запис до робочої частоти 72 кГц (4 відліки на символ).
2. Відфільтрувати RRC-фільтром, узгодженим із формою символів (matched filter): шум зменшується, а символи стають розрізнимими.
3. Знайти burst'и: ділянки, де потужність помітно вища за шум.
4. Для кожного burst'а окремо знайти, в які моменти зчитувати символи (таймінг), і зчитати їх.
5. Для кожного символу взяти зміну фази відносно попереднього (диференційна демодуляція): фаза несучої скорочується, відновлювати її не треба. Залишковий зсув частоти оцінити й прибрати.
6. Квадрант кожної зміни фази -> 2 біти. Біти burst'а - результат.

Паралельно рахується діагностика: чи придатний вхід, скільки знайдено burst'ів, якість кожного (когерентність, SNR, зсув частоти), чи збігаються відомі послідовності TETRA.

Оркестратор - `pipeline.run` (власного DSP не має). Кожен етап обгорнуто `_guard`: виняток стає fatal-знахідкою в звіті, а не падінням.

## Етапи

### Ресемплінг і RRC-фільтр ★
`front_end.to_work_rate`: `resample_poly` до 72 кГц (без змін, якщо вже 72). `front_end.matched_filter`: RRC (rolloff 0.35, 12 символів) через `oaconvolve`. Вихід - `y`; на ньому працюють усі наступні кроки.

### Пошук burst'ів ★
`burst_search.search_bursts` працює на потужності `|y|²` послідовністю чистих функцій (проміжні результати - у `SearchResult`):

1. обвідна = ковзне середнє потужності (8 символів);
2. підлога шуму = 10-й перцентиль обвідної за весь запис (`global`; є також `local`, `fixed`);
3. гістерезис: область над підлогою +5 дБ вважається burst'ом, якщо десь піднімається над підлогою +8 дБ;
4. склеїти провали до 8 символів, відкинути коротші за 100 символів, зрізати по 4 символи з країв (рампи).

Параметри - `SearchConfig` (`SEARCH_*` у `config.py`). Підлога глобальна, тому в записі майже без пауз вона завищена, і burst'и губляться (діагностується в `checks`).

### Таймінг і символи ★
Для кожного burst'а окремо. `symbols.estimate_timing` (Oerder-Meyr): потужність має лінію на символьній частоті, її фаза дає дробову затримку `tau`. `symbols.sample_symbols`: burst підвищується в 4 рази й береться кожен четвертий відлік, починаючи з `tau`. `tau` постійний на весь burst: дрейф тактової частоти всередині burst'а не відстежується.

### Демодуляція ★
`pipeline.demod_burst` викликає `demod.py`:
1. `diff_demod`: `d[k] = s[k]·conj(s[k-1])`, нормовано.
2. Ідеальні фази `d` - ±π/4, ±3π/4, тож `d⁴ = −1` для будь-яких даних. Звідси `estimate_freq_offset`: `θ = arg(−mean(d⁴))/4` - залишковий зсув частоти, однозначний при |f| < 2250 Гц (symbol_rate/8). `correct_freq` повертає `d` на `−θ`.
3. `map_dibits`: квадрант `d` -> два біти за таблицею `DIBIT_BY_QUADRANT` (`config.py`).

### Якість і прапорці ◐
`demod.quality_metrics`: `coherence = |mean(d⁴)|` (1 - ідеально, ~0 - шум або не та модуляція), `phase_rms_deg`. Burst з `coherence < quality.min_coherence` відкидається (за замовчуванням 0 - не відкидати). Прапорці в колонці `flags`: `LOWCOH` (< 0.5), `NEARLIM` (зсув частоти > 0.8 межі).

### Діагностика ◐
`checks.py`: вхід (fs, NaN, рівні, кліппінг), спектр (центр, ширина, символьна лінія), активність, статистика burst'ів, збіги відомих послідовностей. Результат - `HealthReport`; код виходу 0 (ok/degraded), 1 (degraded з `--strict`), 2 (failed). Не змінює біти, але вирішує, чи довіряти записові.

### Тип burst'а ◐
`pattern_check.classify_burst`: для кожної розкладки з `BURST_LAYOUTS` (DMO і TMO) звіряються всі відомі біти (преамбула, FCF, навчальна послідовність, tail), допуск 10 %. Перемагає найменша частка помилок. Це лише мітка `type` і вирівнювання `.bin4`; демодуляції це не стосується.

## Що де міняти

| Питання                       | Місце                                                              |
| ----------------------------- | ------------------------------------------------------------------ |
| Burst'и пропущено / розірвано | `SEARCH_*` у `config.py`, `burst_search.py`                        |
| Біти інвертовані/переставлені | `DIBIT_BY_QUADRANT`, `demod.map_dibits`                            |
| Зсув частоти за межею         | `checks.check_spectrum` (грубий зсув центру), `demod.ambiguity_hz` |
| Низька когерентність          | спершу межі burst'ів, потім SNR                                    |

## Обмеження
- Таймінг і частота - одне значення на burst, без стеження всередині.
- Грубий зсув частоти не коригується, лише діагностується.
- Біти без канального захисту: деперемежіння, FEC, CRC робить наступний етап (для DMO - `dmo_rx`).
