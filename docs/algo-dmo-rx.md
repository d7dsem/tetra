# dmo_rx: алгоритм

Файл бітів (1 біт = 1 байт, 0/1) -> знайдені DMO burst'и -> канальне декодування SCH/S, SCH/H, SCH/F, STCH -> TCH-записи для голосового кодека. 
Вхід дає `tetra_demod` (`.bits*`, див. `docs/algo-tetra-demod.md`). 
Розкладки й кодування: `dmo/docs/dmo-phy-spec.md` (EN 300 396-2), `dmo/docs/dmo-mac-spec.md` (EN 300 396-3).

Пріоритет: **★** ядро, **◐** важливо, **○** допоміжне.

## Схема

```
bits ─find─> [DSB | DNB1 | DNB2 @ start] ─┬─ DSB : SCH/S + SCH/H ─> поля, колір-код (MNI, src)
                                          └─ DNB : descramble(колір-код) ─> SCH/F | STCH | TCH
                                                                     TCH ─> STEM.tch ─> bin/dmo_voice ─> WAV
```

Вхід, цикл і вивід - `dmo/dmo_rx_entry.c`, `main` (`:216`). Константи розкладки - тільки `dmo/dmo_core/dmo_tuning.h`.

## Етапи

### 1. Пошук burst'ів ★
`dmo_find_bursts` (`dmo_core/dmo_find.c:40`): ковзає по потоку на кожному зсуві `start` (поки burst довжиною 470 біт вміщується) і перевіряє відомі послідовності:

| Тип  | Ознака                                                  | Допуск помилок |
| ---- | ------------------------------------------------------- | -------------- |
| DSB  | STS (38 біт) на зсуві 214                               | 0              |
| DNB1 | преамбула P1 (12) + NTS1 (22 на 230) + tail 00 (на 468) | 1 / 2 / 0      |
| DNB2 | P2 + NTS2 + tail 00                                     | 1 / 2 / 0      |

Перевіряється по порядку DSB → DNB1 → DNB2, перший збіг виграє. Допуски - `DMO_*_MAX_BIT_ERRORS` у `dmo_tuning.h`. Знайдений burst не «з'їдає» біти: сусідні зсуви теж перевіряються, тож один burst з хибним збігом поруч може дати два записи. Пошук - єдина точка синхронізації; `.bits4` (вирівняний за типом) не обов'язковий.

### 2. DSB: SCH/S і SCH/H ★
`decode_dsb` (`dmo_rx_entry.c:94`): `dmo_burst_slice` (`dmo_burst.c`) вирізає блоки зі зсувів 94 (SCH/S, 120 біт) і 252 (SCH/H, 216 біт). Обидва декодуються з **фіксованим** скремблером колір-коду 0 (`DMO_SCRAMB_INIT=3`): для DSB так задано стандартом.

Ланцюг блоку - `dmo_block_decode_scr` (`dmo_core/dmo_block.c:46`), у порядку приймача:
1. `dmo_descramble` (type-5 → type-4) - скремблер із сирців osmo-tetra;
2. `block_deinterleave` (параметр `a`: SCH/S 11, SCH/H 101, SCH/F 103);
3. `tetra_rcpc_depunct` (RCPC 2/3) -> материнський код;
4. `viterbi_dec_sb1_wrapper` -> type-2 біти;
5. CRC-16: залишок `0x1d0f` по `type1 + CRC`; `tail_zero` - чи нулі після CRC (додаткова перевірка).

Кроки 2-4 - «листові» файли osmo-tetra (`dmo/osmo_leaf`); власного коду тут лише обв'язка й параметри блоків (`dmo_sch_s_params`, `dmo_sch_h_params`, `dmo_sch_f_params`).

### 3. Поля DSB ◐
`dmo_parse_sch_s` / `dmo_parse_sch_h` (`dmo_core/dmo_parse.c`): бітові зрізи фіксованих позицій у type-1. SCH/S: колір системи, тип PDU, тип зв'язку, слот (1..4), кадр, стан шифрування. SCH/H: лічильник, адреси призначення/джерела, MNI, тип повідомлення (`dmo_msg_type_name`). SCH/H розбирається тільки якщо **обидва** CRC ок і тип зв'язку 00/01 (для 10/11 розкладка не реалізована; блок лишається нерозібраним).

### 4. Колір-код ★ (зв'язок DSB → DNB)
DNB скремблюються колір-кодом з MNI (молодші 6 біт) та адреси джерела (`dmo_scramb_init_dcc`, `dmo_block.c:26`; `init = (E << 2) | 3`). Їх бере `decode_dsb` з SCH/H:
- **strong** - з останнього повідомлення виклику (DM-SETUP, DM-CONNECT ACK, DM-OCCUPIED; `is_call_message`);
- **weak** - з будь-якого останнього декодованого DSB.

Для DNB береться strong, інакше weak (`main`, `dmo_rx_entry.c`). Файл обробляється послідовно: DNB, що стоїть **до** першого декодованого DSB, позначається `no colour code` і не декодується. Колір-код - одне значення на весь прохід (змінюється при нових DSB, але назад у часі не застосовується).

### 5. DNB: SCH/F, STCH, TCH ★
`decode_dnb` (`dmo_rx_entry.c:126`):
- **DNB2**: перший блок (зсув 14, 216 біт) декодується як STCH (параметри SCH/H); результат OK/FAIL за CRC. Другий блок не декодується.
- **DNB1**: обидва блоки (зсуви 14 і 252) зливаються у 432 біти й декодуються як SCH/F. CRC ок -> `SCH/F`. **CRC не збігся -> вважається TCH**: type-4 біти (після дескремблювання, без FEC) пишуться в `STEM.tch` через `dmo_traffic_record` (690 × int16: 6 синхрослів `0x6b21..`, м'які біти ±127; формат дампа трафіку osmo-tetra для `cdecoder`).

Евристика «DNB1 з невдалим CRC = голос» ◐: не відрізняє TCH від зіпсованого SCH/F. Під хибний TCH потрапляє будь-який DNB1 з помилками, тому голосові записи треба слухати, а не вважати достовірними за лічильником.

### 6. Вивід ○
Заголовок `#` (лічильники burst'ів, CRC ok, колір-код, кількість TCH), далі рядок на burst (`print_rec`); `-v` додає біти полів. Код виходу: 0 ok, 1 помилка вводу/пам'яті/запису, 2 аргументи. `bin/dmo_voice` (`.tch` -> WAV 8 кГц через ETSI `cdecoder`/`sdecoder` з `/tetra/bin`) - окремий скрипт, кодек не інтегровано.

## Що де міняти

| Питання                          | Місце                                                      |
| -------------------------------- | ---------------------------------------------------------- |
| Менше/більше пропущених burst'ів | допуски в `dmo_tuning.h`                                   |
| Нова розкладка, зсув, довжина    | лише `dmo_tuning.h`                                        |
| Нове поле SCH/S, SCH/H           | `dmo_parse.c`, `dmo_core.h`                                |
| Інший тип блоку                  | `struct dmo_block_params` + інтерлівер `a` у `dmo_block.c` |
| Логіка колір-коду, TCH           | `decode_dsb`, `decode_dnb` у `dmo_rx_entry.c`              |

## Обмеження
- Пошук - жорсткий збіг бітів послідовностей з малим допуском; на слабкому сигналі burst'и губляться ще до декодування (причину шукати в `tetra_demod`: частка помилок бітів).
- Тільки DSB, DNB1, DNB2; SCH/H для типів зв'язку 10/11 не розбирається.
- `dmo_sync_find` (`dmo_sync.c`) збирається, але `dmo_rx` не використовує - його замінив `dmo_find_bursts`.
- Аудіо: кодек зовнішній
