# dmo_rx: алгоритм

**Призначення.** З бітів, які дав `tetra_demod`, знайти burst'и прямого режиму DMO (зв'язок без базової станції), розпізнати їх, зняти канальний захист і отримати: службові поля (хто, кому, який тип повідомлення), колір-код і записи голосового трафіку.
**Вхід:** файл бітів, 1 біт = 1 байт (0/1): `.bits` або `.bits4` від `tetra_demod` (`docs/algo-tetra-demod.md`). **Вихід:** звіт у stdout (підсумок і рядок на burst) і `STEM.tch` (записи голосу, лише якщо вони є). Далі `bin/dmo_voice STEM.tch` робить із `.tch` файл WAV.
Розкладки й кодування: `dmo/docs/dmo-phy-spec.md` (EN 300 396-2), `dmo/docs/dmo-mac-spec.md` (EN 300 396-3).

Пріоритет: **★** ядро, **◐** важливо, **○** допоміжне.

## Алгоритм одним поглядом

1. Пройти потік бітів і на кожному зсуві перевірити, чи починається там відомий burst: за відомою послідовністю на фіксованому місці (синхро- або навчальною). Так знаходяться burst'и трьох типів.
2. Burst синхронізації (DSB) несе два службових блоки. Їх зняти: дескремблювання, деперемежіння, відновлення пропущених бітів, декодування Вітербі, перевірка CRC. З них прочитати поля, зокрема ідентифікатор мережі (MNI) й адресу джерела.
3. З MNI й адреси джерела зібрати колір-код: за ним скремблюються всі нормальні burst'и (DNB) цього зв'язку.
4. Нормальний burst, що йде після DSB: дескремблювати колір-кодом. Якщо CRC як у службового каналу SCH/F збігся - це сигналізація. Не збігся - вважається голосом (TCH).
5. Голосові біти далі в `dmo_rx` не декодуються: вони записуються в `.tch` у форматі зовнішнього кодека, який робить решту (розділ «Шлях голосу»).

## Етапи

### Пошук burst'ів ★
`dmo_find_bursts` ковзає по потоку (поки 470 біт burst'а вміщуються) і на кожному зсуві перевіряє:

| Тип  | Ознака                                         | Допуск помилок |
| ---- | ---------------------------------------------- | -------------- |
| DSB  | STS (38 біт) на зсуві 214                      | 0              |
| DNB1 | преамбула P1 (12) + NTS1 (22 на 230) + tail 00 | 1 / 2 / 0      |
| DNB2 | преамбула P2 + NTS2 + tail 00                  | 1 / 2 / 0      |

Порядок перевірки DSB -> DNB1 -> DNB2, перший збіг виграє. Допуски - `DMO_*_MAX_BIT_ERRORS` у `dmo_tuning.h`. Знайдений burst не виключає сусідні зсуви: хибний збіг поруч може дати другий запис.

### Декодування блоку ★
`dmo_block_decode_scr` (`dmo_block.c`), у порядку приймача: дескремблювання -> деперемежіння (параметр `a`: SCH/S 11, SCH/H 101, SCH/F 103) -> депанктурування RCPC 2/3 -> Вітербі -> CRC-16 (залишок `0x1d0f`). Додатково перевіряється, що після CRC лише нулі (`tail_zero`). Ланцюг один для всіх блоків; `dmo_rx` викликає його для SCH/S, SCH/H, SCH/F і STCH, змінюючи лише параметри блоку.

### DSB: службові блоки ★
`decode_dsb`: з DSB береться SCH/S (зсув 94, 120 біт) і SCH/H (зсув 252, 216 біт). Обидва скремблюються **фіксованим** колір-кодом 0 (так задано для DSB). Поля (`dmo_parse.c`, ◐): у SCH/S - слот, кадр, стан шифрування; у SCH/H - тип повідомлення, адреси, лічильник, MNI. SCH/H розбирається, якщо обидва CRC ок і тип зв'язку 00 або 01.

### Колір-код ★
DNB скремблюються колір-кодом, зібраним із 6 молодших біт MNI та 24-бітної адреси джерела (`dmo_scramb_init_dcc`). Його дає найближчий DSB:
- **strong** - з повідомлення виклику (DM-SETUP, DM-CONNECT ACK, DM-OCCUPIED);
- **weak** - з будь-якого іншого декодованого DSB.

Для DNB береться strong, інакше weak. Файл читається послідовно: DNB, який стоїть до першого декодованого DSB, не має колір-коду й не декодується.

### DNB: сигналізація чи голос ★
`decode_dnb`:
- **DNB2**: перший блок (зсув 14, 216 біт) як STCH (швидкий службовий канал); OK/FAIL за CRC. Другий блок не декодується.
- **DNB1**: обидва блоки (зсуви 14 і 252) зливаються у 432 біти й декодуються як SCH/F. CRC ок -> сигналізація. CRC не збігся -> **вважається голосом** і записується в `.tch`.

Цей поділ - евристика: зіпсований SCH/F теж потрапить у голос. Лічильникові TCH як доказові наявності голосу довіряти не можна.

## Шлях голосу

1. **Burst.** `tetra_demod` дає біти; `dmo_find_bursts` знаходить DNB1 (преамбула P1 + NTS1).
2. **Біти.** Два блоки по 216 біт зливаються в 432 біти й дескремблюються колір-кодом із DSB. Деперемежіння й виправлення помилок тут **не** робляться.
3. **Запис.** `dmo_traffic_record` пакує 432 біти в запис із 690 значень `int16` (6 синхрослів `0x6B21...` + «м'які» біти ±127). Це формат входу кодека `cdecoder`, такий самий, як у трафік-дампі osmo-tetra. Записи йдуть підряд у `STEM.tch`. За `docs/dev-notes.md`, 1 запис = 60 мс мовлення.
4. **`cdecoder`** (канальний декодер з ETSI reference codec у `/tetra/bin`): за його usage читає такі записи й видає по 138 біт на кадр: ознака пошкодженого кадру (BFI) + 137 біт стисненого мовлення.
5. **`sdecoder`** (мовленнєвий декодер того ж кодека): розпаковує ці біти (стиснення ACELP) у PCM-відліки.
6. **WAV.** `bin/dmo_voice` загортає PCM у WAV (8 кГц, mono, int16, за замовчуванням `<ім'я>_audio.wav`).

Слабкі місця: вибір «голос = CRC SCH/F не збігся» (див. вище) і те, що `dmo_rx` не перевіряє коректність звуку. Наявність WAV не доводить, що голос декодовано правильно.

## Словник

| Термін              | Значення                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| DMO                 | прямий режим: абоненти зв'язуються напряму, без базової станції                                |
| DSB                 | burst синхронізації: відома послідовність STS і два службові блоки SCH/S, SCH/H                |
| DNB1, DNB2          | нормальний burst: DNB1 - голос або один повний службовий блок, DNB2 - з швидким службовим STCH |
| SCH/S, SCH/H, SCH/F | службові канали: синхронізаційний, на півслота, на повний слот                                 |
| STCH                | швидкий службовий канал, що займає місце голосу в слоті                                        |
| TCH                 | канал голосового трафіку                                                                       |
| Колір-код           | значення, що задає скремблювання; складається з MNI й адреси джерела                           |
| type-1 ... type-5   | стадії бітів: type-1 - корисні; type-4 - після кодування; type-5 - після скремблювання         |
| MNI                 | ідентифікатор мережі (країна + мережа)                                                         |

## Що де міняти

| Питання                          | Місце                                                      |
| -------------------------------- | ---------------------------------------------------------- |
| Менше/більше пропущених burst'ів | допуски в `dmo_tuning.h`                                   |
| Нова розкладка, зсув, довжина    | лише `dmo_tuning.h`                                        |
| Нове поле SCH/S, SCH/H           | `dmo_parse.c`, `dmo_core.h`                                |
| Інший тип блоку                  | `struct dmo_block_params` + інтерлівер `a` у `dmo_block.c` |
| Логіка колір-коду, голосу        | `decode_dsb`, `decode_dnb` у `dmo_rx_entry.c`              |

## Обмеження
- Пошук - жорсткий збіг бітів із малим допуском; на слабкому сигналі burst'и губляться ще до декодування (причину шукати у `tetra_demod`).
- Тільки DSB, DNB1, DNB2; SCH/H для типів зв'язку 10 і 11 не розбирається.
- Колір-код один на прохід: змінюється з новими DSB, назад у часі не застосовується.
- Голос: евристика вибору TCH, кодек зовнішній, коректність звуку не перевіряється.
